# Xbox prototype runtime observation

The Xenia adapter now records actual script entry and opcode dispatch from both supplied complete prototype builds. It uses official Canary commit `c3cd8617b18ef018ea8d638c865e0cced7399846` and BMT's existing local runtime protocol. Authored source, reproducible overlay preparation, launch isolation, and bounded protocol checks are under [`tools/XeniaRuntimeBridge`](../tools/XeniaRuntimeBridge/README.md).

The first two-build observation milestone passed; binary SHA256 is `270804ea8242e9b8880ecada768bb0bdc9ee9363f3ad41306199311466129966`. July rendered version `0.14.32.169`; the 2011 bundle rendered `1.3.0.373`. Five-second captures imported as complete: July 2,947 events including 2,538 opcode dispatches; 2011 4,108 including 3,343. Both had zero drops, missing sequence numbers, or import diagnostics. Both passed eight live protocol checks covering cancel, unsupported actions, reconnect, and stopping. Original XEX hashes were unchanged; all emulator processes closed normally.

Receipts: [`two-build-validation.json`](../artifacts/prototype-runtime/xenia/evidence/two-build-validation.json), [July trace](../artifacts/prototype-runtime/xenia/runs/july/attempt-003/capture-002.ndjson), [2011 trace](../artifacts/prototype-runtime/xenia/runs/2011/attempt-002/capture-001.ndjson). Failed earlier attempts are preserved. July's first hidden-state capture contained only lifecycle events; the successful capture followed window restoration.

The 2011 patched XEX does **not** match its bundled PE/PDB. Actual CodeView GUID is `5B7FD6B4-EEFE-4F75-B919-89BBDE89BB56`; supplied symbols identify `B9849415-92B3-43DB-8256-FC262E2A77F5`. Its profile therefore records full-function instruction correspondence, including independent callee comparisons and Run's direct call into EvaluateLine, followed by exact live entry checks. This is distinct from July's matching-symbol basis. See [profile proof](../artifacts/prototype-runtime/xenia/evidence/2011-profile-proof.json). No blanket symbol/layout coverage is implied for other builds or the November–April memory captures.

Unknown guest-hash rejection also passed using a synthetic artifact copy with one trailing zero byte. The adapter rejected it before guest execution; source inputs remained unchanged. [Fixture receipts](../artifacts/prototype-runtime/xenia/runs/unknown-profile-rejection/fixture.json) distinguish this negative test from a genuine build.

The probes observe function dispatch, not success or outcomes. These captures occurred at title/boot screens. Opcode, bytecode offset and current line use the verified function argument ABI; the original traces retain raw Script-pointer prefixes. The follow-up below adds validated Script identity and one controlled condition handler; general numerical state, full CTDA traces, message choice, gameplay commands and combat attribution remain unavailable. Main::RunScripts did not execute, so the documented entry counter remains zero. Non-quick-exit destructor shutdown is not yet exercised end to end. These limits keep this milestone separate from completion of the wider runtime experiment plan.

The backing follow-up is implemented; its 313-step native build passed with one worker, SHA256 `cb8a58f806e714a657de41ddfb548c9bf9b17aff58d1627014a663c7563da51f`. [Build receipt](../artifacts/prototype-runtime/xenia/evidence/backing-build-validation.json). A successful Xenia host open supplies the exact handle used for a bounded full SHA-256 read. Before/after handle metadata must agree; the observer retains alternatives and failed reads. Hashing holds no capture or backing-map lock. The controller's `runtime guest-prepare` pins the emulator, guest and candidate plugin files; `runtime capture --guest-manifest` checks those identities again and joins only the actual ordered guest table to one matching read-only open observation per active plugin. This does not infer load order from the candidate directory. `RuntimeGuestManifestTests` covers complete shared binding, reversed engine order, changed files, ambiguous/missing observations and identity rejection; `RuntimeIsolationTests` also checks backend/evidence calibration.

[First-live receipts](../artifacts/prototype-runtime/xenia/evidence/backing-first-live-validation.json).

Source review identified a transport defect exposed by these checks: `PIPE_NOWAIT` output treated any successful short/zero write as fatal while capture-start enrichment temporarily pauses reads. The narrow follow-up retains one bounded packet and its offset, retries without duplicating bytes, and continues admitting control requests; genuine pipe failures still disconnect. Two parameterized fixtures passed with real full-pipe backpressure, exact ordered drain and closed-client failure, plus injected positive-short-write coverage. The initial test incorrectly assumed the local kernel must produce a positive short write into an undersized pipe; it was corrected to test the production buffer size and cover each permitted branch separately. Native relink and both-build replay are pending. [Windows pipe contract](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-type-read-and-wait-modes).

The wire namespace contribution is limited to 60 KiB, falling back to an explicit partial query with empty entries. A final 64 KiB event guard reports loss without emitting invalid JSON. Metadata agreement is not an atomic file snapshot; captures retain the successful-open-handle scope and the separate manifest identity. Older captures remain unbound and unchanged.

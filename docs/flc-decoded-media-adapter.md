# Bounded FLC/CEL decoded-media prerequisite

This staged application adapter targets Shared `20e4e2c0fb2d304ed60c05e48d8c97a9a730b684` and the [existing classic-media coordination requirements](classic-media-adoption.md). It is not yet compiled or executed. Existing permissive `FlicFile.Parse` callers, classic preview dispatch and timers remain unchanged. VID delay/A/V-origin semantics remain unresolved and are not inferred by this slice.

[`FlicDecodedMediaDecoder`](../src/BethesdaMultitool/Core/Formats/Xngine/Flic/FlicDecodedMediaDecoder.cs) prepares detached indexed frames through a new strict profile, then exposes Shared's existing `IDecodedMediaDecoder`. The profile admits Arena-style FLC `0xAF12`, 8-bit indices, positive canvas size and positive unsigned header milliseconds. `MillisecondsPerFrame` retains that exact integer; timestamps/durations use checked integer ticks. Every display slot, including palette-only and empty holds, occupies its declared duration. CEL prefixes and known preview stamps do not become displayed frames. The extra ring block must reproduce the first image indices and complete palette before being removed.

Strict admission accepts proven whole-palette updates and supported full/delta frame chunks. Unknown chunks, partial palettes, zero-speed files, unrecognized reserved fields/control words, malformed clipped runs and out-of-canvas delta row progress decline explicitly. The permissive parser remains available to existing routes; this adapter does not install a fallback or replace their capabilities.

Default [`FlicDecodeLimits`](../src/BethesdaMultitool/Core/Formats/Xngine/Flic/FlicDecodeLimits.cs) cap encoded input at 64 MiB, canvas at 4 Mi pixels, actual picture blocks at 4,097 including ring, and charged decoded allocation at 256 MiB. Admission precedes canvas/RGBA, frame snapshots and palette allocations; actual blocks are counted independently of the declared frame count. Ring/superseded palette allocations are charged. Objects/list overhead, caller-owned encoded memory and Shared retained sample copies are separate. Cancellation checkpoints cover source/chunk/packet/row work; synchronous operations are not forcibly interrupted.

The single video track uses caller-supplied occurrence identity. Audio is explicitly absent; aspect/platform data are not invented. Seeking floors to an indexed display boundary and clamps beyond duration to EOF. Replay requires an explicit seek to zero. The decoder's reusable RGBA buffer is borrowed only until the next decoder call; Shared `DecodedMediaSession` supplies independently retained samples. Construction takes an optional input lease only on successful completion. Disposal serializes against conversions, publishes its terminal task before retiring input, and retains failed ownership without implicit retry.

That receipt is prior-implementation output, not an independent codec/engine oracle. The new adapter has not yet demonstrated parity. The staged filter contains **47 cases**: 28 new synthetic adapter cases, 17 existing parser regressions and two serial opt-in retail rows. The retail rows pin source/hash/header identities and every frame hash, reverse indexed seeks with half-frame requests, EOF and full replay, using one retained Shared sample. They allow at most 2 MiB encoded, 64,000 canvas pixels, 91 picture blocks and 8 MiB charged decode storage.

Compilation/analyzers, these cases and the new adapter's actual private parity remain pending. Native media bridge/GUI playback, timer replacement, seeking UX, source replacement/shutdown and independent release acceptance require subsequent work with the Shared media owner. This prerequisite does not complete classic-media adoption.

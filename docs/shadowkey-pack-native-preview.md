## Catalog and selection authority

Candidate detection checks the real non-folder node's known filename without reading payloads on the UI thread. `OpenAsync` requires a `BethesdaBrowseSource` and reference equality between the node's ancestor root and the opening's fixed tree root. Same-path objects from another opening do not acquire authority. The existing tree/check/export model is retained: slot rows are not additional `AssetNode` or VFS entries, and selecting a slot does not add an export check.

The catalog reads siblings in the selected virtual directory using `VfsPath`. It does not use host filesystem path matching or search other directories for similarly named resources.

| Input | Requirement and maximum | Validation |
| --- | --- | --- |
| `models.idx` | Required; 32,772 bytes (`4 + 8 × 4096`) | Exact declared-length match; at most 4,096 slots; offsets tile the pack contiguously. |
| Selected `models.huge` | Required; 32 MiB | Returned path matches the requested virtual path; every index extent is inside the pack and the final extent ends at its exact length. |
| `models.txt` | Optional; 1 MiB | Strict UTF-8, with optional BOM; present entries form the existing parallel ordinal table. A present unreadable, malformed or over-budget file fails instead of becoming an anonymous fallback. |

The required index is read first, so its absence prevents a pack read. Structural index parsing follows the companion reads. Each successful read retains its actual `GameFileReadResult.Entry`, including the readable layer that supplied those bytes. Companions may come from different layers under existing VFS precedence; no common layer is inferred from earlier enumeration metadata. These are source records, not content hashes or an atomic three-file filesystem snapshot.

`PackReference` retains the real pack path and source ID. An immutable `ShadowkeyPackSelection` adds `shadowkey-slot:<ordinal>` as an occurrence token and retains the exact catalog plus frame, skin and keying choice. Duplicate or missing names remain display information. Snapshot reference and generation identify the opening; the selection object and browser request revision identify the attempt. The document's source identity serializes source ID, snapshot generation, real pack path, occurrence, slot and each companion's actual source label. Existing document/node extras retain selected frame, selected skin, source frame count and the color-key choice.

## Preparation and native handoff

`OpenAsync` links source retirement with caller cancellation and retains a `BrowserLease` until its worker returns. It copies the bounded pack buffer before retaining it because a VFS implementation may keep its returned array. Index data becomes immutable entry values; names become strings. The exposed entry collection is copied and read-only. The resulting catalog owns managed data and borrows snapshot identity; it holds no long-lived filesystem lease.

`Prepare` rejects a selection from another catalog and parses only the selected entry into fresh parser arrays. It deliberately avoids `ShadowkeyModelPack.GetMesh`'s mutable lazy cache. Parsing one record still reads that record's complete frames and skins. Repeated or concurrent preparation therefore uses independent parser/scene data, with repeated per-record allocation; it does not parse every record or reread the VFS. Empty and unsupported records retain an explicit reason and selection. A corrupt selected record throws without invalidating unrelated slots.

Cancellation is checked before and after existing synchronous reads/parsing and at the adapter's existing boundaries. Those operations are not newly interruptible internally. The read lease remains alive until canceled work actually returns. The 32 MiB limit is an input bound: the original VFS buffer and detached copy can coexist, and parsed arrays, decoded pixels, encoded PNG, scene ownership copies and native resources add memory. There is no new aggregate memory admission controller in this catalog.

The browser runs preparation and bounds measurement off the UI thread, then checks exact snapshot, browser generation, request revision, catalog, selection and selected slot before publication and again inside the presenter factory. It hands the existing `ModelDocument` directly to [NativeScenePresenter](../shared/Multitool.Shared/src/Slfx77.Multitool.WinUI.Direct3D12/Scenes/NativeScenePresenter.cs) with that same snapshot. Shared acquires a separate native input lease. There is no GLB serialization/import or whole-pack-as-one-mesh conversion.

The retained controls initially select slot zero, frame zero, skin zero and opaque colors. Frame/skin ranges come from the parsed record. Changing options on the same catalog/slot captures the current camera before canceling the old request; another slot or catalog frames afresh. Bounds use `ScenePoseEvaluator` and `ScenePresentationWorkspace` over the exact document, with a 128 MiB pose-workspace limit and the adapter's existing Y-up units. Shared owns its existing renderer/image budgets, input, inspection, capture controls and camera behavior. `Automatic` texture filtering retains Shared's level-zero policy; this slice invents no mipmaps or world-unit scale.

## Replacement and retirement review

The Core, browser and window-owner patches were independently reviewed together against the pinned Shared APIs before application. The review identified a real source-close race: an old close could await native retirement while a later close attached a new source, allowing the old continuation to capture and release the new source fields. The applied close chain publishes its task and claims the generation synchronously, blocks source/selection admission, and awaits its predecessor before touching source fields. Only the latest close may reopen admission. `AttachWorkspaceSourceAsync` also rejects disposal before acquiring a lease or appending a close.

Preview requests publish the new revision, cancellation source and tracked task before canceling their predecessor. They observe and drain preceding work before clearing/adopting. Source close captures the exact pending task and cancellation source, revokes catalog/selection authority, and completes native clearing before releasing the existing source lease. Late presentation failures must match the exact selection, snapshot and Shared request; stale callbacks cannot clear a newer selection.

Disposal publishes one retained result before callbacks can reenter. The Assets pane first observes any source-close result, drains all caller preparation/adoption work, and independently awaits presenter disposal. `NativeResourcesRetired` is true before configuration and becomes true after configuration only when that awaited native disposal succeeds. Explore retains the workspace source if this proof is absent. MainWindow keeps graphics, localization, window chrome and HWND prerequisites and blocks final close if native graphics cannot retire safely. Recovery remains outside this preview route.

A failed Shared disposal returns the same failed retirement task; this integration does not pretend it supports a release retry, recreate the presenter, or close the window anyway. A prior source-clear error is preserved in the aggregate result. If the independent final presenter disposal succeeds, the already-settled source-close chain can be reset solely to release retained source fields; the presenter is then null, so this does not retry failed native cleanup. Construction failure after native configuration likewise leaves retirement unproven rather than publishing a success flag. These are reviewed control-flow properties, not executed failure-path acceptance.

## Current limits and acceptance gates

This slice adds one Shadowkey pack workflow. It does not complete the native-viewer migration, M1–M6, release acceptance, CLI/export adoption, zone/entity composition or animation support. Optional magenta transparency remains a user-selected hypothesis; opaque is the default, and opt-in keying carries the matching mask material. Authored multi-frame sequence rates still decline because their timing units are unknown. Selecting another frame does not override that decline. Alternative skins are whole-mesh choices; entity-table selection is not inferred. Unsupported slots show a reason; this increment does not supply an alternate animated native renderer.

The [20 new portable cases](../tests/BethesdaMultitool.Tests/Core/AssetBrowse/ShadowkeyPackPreviewSourceTests.cs) pass on Windows and Ubuntu WSL with zero skips. They cover duplicate labels/exact slots, absent and invalid companions, actual mixed-layer provenance, detached buffer ownership, selected corruption isolation, source replacement while a read is blocked, cancellation, old-opening rejection, exact option forwarding and concurrent independent preparation. The [current 152-case receipt](validation/shadowkey-native-preview-20260920.md) records compiled-source and binary correspondence, including the two accessibility checks. Ubuntu runs the Windows-built portable payload. The [earlier adapter evidence](shadowkey-neutral-fidelity.md) and [54-case validation receipt](validation/travels-fidelity-20260920.md) retain their earlier scope.

The [Windows native checkpoint](validation/shadowkey-native-preview-20260920.md) binds compilation and captures to application DLL `73822d9bef3b17c1db74def2d1ea52373579e9cee47d879bd81620318596bb7a` and its source freeze. Fern opaque and explicit-key plus arrow opaque each produced a 512×512 PNG and receipt after successful native disposal; empty/animated slots declined without outputs, and an existing destination was preserved. Independent fern checks passed 111 opaque and 90 keyed stable samples, with zero errors above the fixed tolerance and a maximum channel error of 3.1385181496. This proves bounded offscreen texture/key/repeat behavior for those camera/selection choices. It does not exercise `NativeScenePresenter`'s retained GUI, prove a GUI `PresentedRevision`/`PresentationGeneration`, or establish original-game magenta-alpha policy. Follow-on source edits are not covered by those capture hashes.

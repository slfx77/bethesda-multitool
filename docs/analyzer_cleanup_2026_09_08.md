## Triage and exception candidates

- Fix compiler failures and demonstrated defects first, including invalid shifts/division, resource lifetimes, nullability mismatches, and discarded computations.
- Keep exact floating-point comparisons where they represent format sentinels, identity, or independently pinned test expectations. Do not introduce arbitrary tolerances to silence diagnostics.
- Domain names, binary signatures, game strings, shader symbols, and synthetic test data are legitimate spelling exceptions. Correct ordinary prose typos without changing serialized names or external contracts.
- Test names deliberately describe behavior; reflection-discovered tests and fixtures may appear unused. Verify discovery and callers before removing members.
- Captured disposables are safe only when all callbacks finish inside their lifetime. Synchronous assertions and awaited operations can produce inspection false positives; escaping callbacks require repair.
- Defensive parser checks and intentionally invalid synthetic data can contradict nullable annotations or static value analysis. Retain checks that validate untrusted input and tests that exercise rejection behavior.
- Existing WinUI inspection exclusions and DDXConv submodule boundaries must be respected. Localization of diagnostic logging and broad language-style rewrites need a concrete benefit.
- Source-contract tests can fail after valid ReSharper syntax changes. Prefer behavior tests where possible; update necessary source assertions to preserve the original invariant.

No new blanket suppression or severity reduction is part of this baseline.

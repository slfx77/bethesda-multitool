## Browsing and ownership

[`AssetBrowserTab.Gallery`](../src/BethesdaMultitool/App/Tabs/AssetBrowser/AssetBrowserTab.Gallery.cs) composes Shared `ThumbnailGallery` and `BrowserFilterToolbar`. The tree remains the scope selector: only its direct Texture/Sprite children enter the gallery, in builder order. List/Thumbnail and literal name/path search retain exact node identities, checked export selections and current previews. Hidden gallery focus returns when visible again; changing folders resets gallery focus. Thumbnail dimensions are labeled as thumbnail dimensions. First launch uses Thumbnails; explicit choices persist as `Browser.Assets.Images.ViewMode` in `workflows.json`. Theme and language retain their existing settings.

Each [`AssetThumbnailLoader`](../src/BethesdaMultitool/App/Tabs/AssetBrowser/AssetThumbnailLoader.cs) captures its exact session/snapshot and receives the source retirement token. The browser publishes its wrapper before starting Shared work, drains the loader before releasing the source lease, and rejects stale row/source callbacks. Failed retirement keeps the owner/source and real observations reachable; observing failure does not implicitly retry cleanup or admit a replacement. Shutdown attempts independent retirement stages and respects existing native-resource prerequisites. The window localization controller is borrowed; accepted settings work drains before controls/subscriptions retire.

Shared owns the decoded queue/cache. BMT explicitly retains **2,048 entries / 64 MiB**. One browser-lifetime [`ThumbnailCacheObservation`](../src/BethesdaMultitool/Core/AssetBrowse/ThumbnailCacheObservation.cs) preserves `AssetBrowserThumbnails` registry diagnostics, actual cumulative source history, and any-thread half/zero pressure trimming. It snapshots actual loader references under a short gate and queries/trims outside it. Successful retirement transfers final scalar counters once; failed/blocked caches remain observable. No second decoded cache, invented counters, decoder call, UI dispatch or source lease is introduced by diagnostics.

## Persistent DDS/DDX thumbnails and clearing

[`DdsThumbnailProducer`](../src/BethesdaMultitool/Core/AssetBrowse/DdsThumbnailProducer.cs) uses one actual VFS read result and its winning source/path/bytes. Its strict length-prefixed key includes physical source identity, merged-path occurrence, actual resolved provenance, metadata size, byte length/SHA256, recipe, cell pixels and display scale. Labels and opening generations are excluded. A hit still reads/hashes the original, saving decode/scale work only. Readable undecodable overrides continue blocking lower layers.

The existing `ApplicationThumbnailCache("BethesdaMultitool")` owner supplies the accepted **512 MiB** optional disk budget. Persistence admits at most 64 MiB source bytes and 64 KiB identity; larger/invalid identities decode uncached from the same read. These are persistence bounds: the existing representable whole-source read, DDS decoder and scaler do not gain a new memory or interruption guarantee. Cancellation is observed around synchronous stages and is never converted into a miss. Sprites remain on their live palette-aware route until actual companion identity is available.

[`AssetBrowserTab.ThumbnailCache`](../src/BethesdaMultitool/App/Tabs/AssetBrowser/AssetBrowserTab.ThumbnailCache.cs) exposes **Clear thumbnail cache** in the image filter flyout. It clears the same application disk owner off-thread, preserving source/preview/memory state. Text identifies stored DDS/DDX thumbnails and warns that browsing may store new thumbnails; it does not promise permanent emptiness during active work. The complete task is published before UI callbacks; shutdown cancels and drains it before later teardown. Localized progress/result text has a stable automation ID and polite live setting. Actual announcements, keyboard/focus behavior and error presentation require GUI evidence.

## Acceptance boundary

The staged portable cases are 8 projection, 5 real cache-observation, and 13 DDS persistence cases including clear/reopen. The clear case verifies disk removal, retained literal pixels/source bytes, regeneration with a fresh owner and a subsequent hit. These are behavioral tests, not source-string mirrors; they do not exercise WinUI worker realization.

Required remaining checks include coordinated locked portable/Windows builds and tests, List/Thumbnail/search/check/focus behavior, live localization and accessibility, source replacement and shutdown during decode/settings/clear work, actual Diagnostics pressure/counters, storage failure/read-only behavior, and DPI/performance measurement. Artwork families, sprites with companion keys, posters, waveforms, portraits and the wider media/viewer workflows remain outside this bounded slice. No complete TB1/TB3 or release acceptance is claimed.

## Ownership

Reverse TESForm attribution now chooses the PDB class through the recovered entry's calibrated FormType. It validates the exact object address, raw FormType, FormID and BSStringT pointer/length using VA-safe reads. A plausible raw header without a recovered identity no longer produces a `FieldNamed` claim; RTTI remains a separate evidence path. Relaxed length matches retain their weaker confidence.

Attribution candidates retain their own supporting pointer VA/file offset. Shared allocations, reverse-pointer matches, RTTI matches and exact-text inventory matches retain competing owners. Selection requires a uniquely validated owner; exact-text, asset-path content, positional and offset-only EditorID matches remain candidates without establishing an owner. Direct EditorID selection validates the raw identity and actual `cFormEditorID` pointer. Competing validated identities stay in `ReferencedOwnerUnknown`, with `HasAmbiguousOwners=true` and no chosen owner/confidence. Exact-text matches have no fabricated pointer path. Overlapping estimated object spans remain conservatively excluded; positional and content-only heuristics retain their existing weak confidence. This is bounded static attribution, not proof that a script or gameplay path used the string.

## Runtime messages

The checked-in PDB describes `BGSMessage.ButtonList` at +64 and each 16-byte `MESSAGEBOX_BUTTON` as `Text` (`BSStringT`) at +0 and `Conditions` (`TESCondition`) at +8. The previous nested ownership helper read text at +8. Typed MESG extraction and string ownership now share a layout-driven reader, including button order and per-button condition lists.

Empty labels retain their index; missing allocations/text/conditions and incomplete/cyclic lists have explicit diagnostics. The MESG model retains item/text VA and file offsets. `TESDescription.lFileOffset` is recorded as a source-file offset with `file-offset-only; description text not recovered`; it is never dereferenced as a VA or reported as proof of an empty description. Linked plugin bytes or an independently mapped source-file page would be needed to recover that text.

The follow-up description recovery now attempts the latter during semantic message parsing. Supplied July PE/PDB evidence shows `LoadDescriptionData` copying `TESFile.m_fileoffset` (+0x264), then `LoadDescription` seeking that offset, checking the form type and iterating chunks. `RuntimeMessageDescriptionRecovery` consequently validates a mapped `MESG` header and exact FormID, then a complete, terminated `DESC` subrecord. It reuses same-capture INFO-calibrated TESFile segments; it never substitutes a different build's text. All candidate mapping paths/statuses and recovered alternatives survive in the model, text/show diagnostics and the additive CSV `RuntimeDescriptionMappings` column. Conflicting valid descriptions remain ambiguous. Uncalibrated/out-of-range, uncaptured bytes, malformed framing, compressed data and the 64 KiB bound remain distinct. Proof: `artifacts/prototype-runtime/xenia/evidence/july-description-disassembly.txt` (Microsoft dumpbin bytes, Capstone PPC32 disassembly and matching PDB publics). The build and real November recheck passed; the checked description remains unavailable.

## Capture corpus recovery (P2-L01)

`dmp dialogue-recovery <dump-or-directory> --formids <hex,hex,...> --output <new-directory> [--recursive] [--ownership]` runs the existing analyzer, semantic parser and dialogue-provenance recovery per capture, sequentially. It writes `corpus.json` plus per-source JSON, recording input and tool SHA256, input stability, requested targets, individual INFO variants, original offsets, mapping statuses, recovered NAM1 response text/result scripts, optional linked ownership candidates and stage timings. Existing nonempty output directories are rejected. Completed-source receipts survive cancellation/failure. Omitted ownership analysis is explicitly `not-run`.

Mapped INFO header and payload reads now use VA-contiguous capture regions, allowing disjoint dump-file storage but rejecting adjacent-file bait across VA gaps. Results distinguish missing header/payload, uncalibrated base, targets outside calibrated ranges, the 64 KiB inspection bound, and compressed payloads this inspector has not decoded. None of those statuses establishes that no alternate representation exists. Responses from another capture remain that capture's evidence; prompts and candidate strings never become NPC replies by association.

The prior audit's exact target seeds are Dobson radio fix `000E44A1`, Taggart `000CDA3D`, Hawkins `000E7459`, and Biggs `001028B7`. Example (choose a fresh output directory):

```text
BethesdaMultitool dmp dialogue-recovery Sample/MemoryDumps --formids 000E44A1,000CDA3D,000E7459,001028B7 --output TestOutput/dialogue-recovery-audit --ownership
```

`DialogueCorpusRecoveryTests` covers VA-contiguous/file-disjoint recovery, header/payload capture gaps, mapped NAM1 text, calibrated ranges, unsupported inspection and target parsing. V4 completed all 50 captures and 250 selected source/INFO pairs, including ownership analysis. All six reply controls and 52 ownership associations match V3; mapping, physical-record and candidate results are unchanged.
